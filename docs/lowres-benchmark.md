# LOWRES-BENCH-01：部署尺寸共同重训

## 目的与已批准设置

比较EdgeFlowNet、MCUFlowNet-S、MCUFlowNet-L在相同低分辨率输入与训练预算下的FP32和INT8表现。不是各模型专项最优配方搜索，也不是作者训练的逐项复现。

- 三模型从零开始，先seed42，正式比较补43、44。
- 整幅图像缩放到共同输入；图像面积插值，光流双线性插值，u/v分别乘宽/高缩放比例。
- FC2 400轮、固定学习率1e-4；FT3D 50轮、固定1e-5。每轮遍历共同清单一次，不用500步代替一轮。
- FT3D采用TRAIN、左相机、Clean+Final、前后方向；最终清单数量及每轮步数须在数据验收后冻结。
- batch32，FP32，Adam beta=(0.9,0.999)、epsilon=1e-8、weight_decay=0，不做梯度裁剪。阶段转换使用FC2末尾模型与BN，新建Adam。
- 统一真实像素位移监督，无标签截断或400掩码；三层多尺度L1及不确定性损失，沿用官方三输出对应权重0.125/0.25/0.5，不确定性项系数1。
- 不新增随机颜色/几何增强、EMA、QAT；prefetch1。
- FC2每10轮、FT3D每轮进行共同Sintel监控；固定终点主结果、统一监控选优为补充。196对既有留出在使用前核对是否已被其他实验用于选优。
- 旧大图训练权重在相同低分辨率与评分清单下作参照；其历史配方不同，不能把全部收益只归因训练尺寸。
- INT8使用相同64对FC2训练样本校准，EPE还原原图坐标、不截断。最终报告独立种子波动。

基础日程来源：https://arxiv.org/html/2411.14576v1#S3.SS1 。真实标签与部署缩图是本研究共同修订，不声称与原作者完全一致。

## 开跑前必须通过

1. 共同尺寸满足部署内存约束；目前208x160存在下述阻碍。
2. 数据清单、方向、缩图和位移单位验收。
3. Edge/S/L在统一训练入口的前后向、BN更新和损失对应关系验收；不能把旧推理模型直接当训练入口。
4. 各模型短跑与中断恢复验收（模型、Adam、BN、步数、样本顺序）。
5. Tier2账户、配额、资源限制和实际GPU环境验收；锁定提交版本后才提交长训。

## 2026-09-27内存预检与更正：208×160尚需按对应固件核验

本机输出：`C:/00Work/Runs/MCUFlowNet/LOWRES-BENCH-01/preflight/`。

旧172×224模型启动记录给出的arena为1,419,872字节，不能用于其他输入尺寸的可部署性判定。旧扫描预算为1,468,006字节；两者不可混同。以旧启动记录中的预算重新运行Vela4.5.0、U55-64、Size模式，使用已有EdgeFlowNet INT8产物：

| 输入宽×高 | 编译SRAM | 与当前arena比较 | CPU算子 |
|---|---:|---|---:|
| 208×160 | 1,464,320 B | 超出44,448 B | 0 |
| 192×144 | 1,216,512 B | 余203,360 B | 0 |

Vela退出码0不代表适配当前固件。上述是旧权重编译证据，尚非实际板端分配和新训练权重验收。

**更正：撤回仅凭上述比较要求改192×144的建议。** 当前源码先按模型尺寸分配帧与可视化缓冲，再从剩余空间动态计算arena，1,419,872 B不是板卡硬上限。硕士论文正文p.19表3.2报告Edge输入156×208的板端DWT=182.8 ms，p.20报告1430 KiB峰值；p.56表7.2区分Edge可部署156×208与S/L172×224。另一个SDK历史版本记录输入157×203、输出160×208及1432 KiB arena。论文与该历史版本输入不同，不能合并为208×160输入已经验收。

维持批准的208×160训练候选，不再要求用户批准缩小；下一步按对应模型、固件和完整缓冲核验精确208×160输入。正式训练尚未提交，不把历史输出208×160等同于输入尺寸。
