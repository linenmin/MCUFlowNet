# DATA-ROUTE-01：继续FC2还是切换FT3D

目的：比较从同一FC2保存点出发，在相同低学习率、输入尺寸、训练步数和增强条件下，更换数据是否改善Sintel。S/L分别比较；不是重复标签截断实验，也不是直接复现旧FT3D配方。

## 固定设置

- 父模型：各自第100轮、69500步的冻结`last`，位于`20260919-fc2-label01-diagnostics/{s,l}_clip50/snapshot`。不使用150轮末尾覆盖父模型。初始化核对模型和BN张量，两个分支都新建Adam，阶段步数归零。
- 四个单卡分支：S-FC2、S-FT3D、L-FC2、L-FT3D。架构、batch/microbatch=32、352×480随机裁剪、种子42、损失、梯度阈值200不变，不加图像或几何增强。
- 每支20000次更新，LR从1e-5余弦降至1e-6。每500步作为一个记录区间，CSV的40个epoch是这些区间，**不是遍历数据集40遍**。每个区间重新洗牌、取前500批，两种数据使用同样规则。
- 两个加载器都以像素为训练/预测单位，训练标签逐分量±50；FT3D设divisor=1。旧FT3D配方的divisor=12.5及强增强不用于这个对照。验证标签保留原值，预测尺度=1；不能拿FT3D内部验证与FC2内部验证直接排名。
- FT3D使用clean+final、左相机、前后向，沿用14条历史排除路径；本次路径验收后有效训练80578、验证15730配对。图像尺寸与有限值只抽样解码，训练采用严格读取，遇到损坏数据报错，不静默换样本。
- FP32、TF32关闭、同一Sofia容器。一卡配24 CPU；FC2加载8线程、FT3D加载16线程、验证8线程，关闭后台预取；线程数不改变配方。数据测试对4/8/16线程的相同批次指纹一致，短测试存在缓存/顺序影响，实际收益看训练的data_seconds/update_seconds。

## 验收和选优

`tools/hpc/run_data_route.py --variant s_ft3d --mode probe`等四组先各执行50步、退出、再恢复至100步。核对父权重、同模型初始指纹、S/L的250/390个训练状态张量恢复、NumPy/Python随机数状态保存，以及Sintel输出单位。probe独立目录，不作为正式起点。

通过后以`--mode train`启动四个独立正式作业，建议每作业12小时；调度账户和资源提交前查询。每1000步做76对快检，每5000步做845对完整监控，196对留出不用。内部数据验证只取顺序前20批作诊断，最终选优看共同Sintel监控；FC2的20批恰好覆盖640对。

比较相同5000/10000/15000/20000步结果和可恢复最佳权重。若FT3D更好，只能归因于本次固定配方下更换数据的效果；若FC2更好，也不能推断历史FT3D完整配方无效。后续可再测试强增强或历史缩放配方，但应独立命名。选中的完整训练方案最终换独立种子重跑。

## 文件与接续

代码入口生成完整JSON配置，保存于`/runs/DATA-ROUTE-01/control/<mode>-<variant>/`，与job manifest一起记录Git提交和父权重SHA256。训练输出位于`/runs/DATA-ROUTE-01/<mode>-<variant>/model_*`。运行索引登记父模型，wiki仅在现有实验总表新增一条研究记录。

训练器支持`updates_per_epoch`，不设置时保持原完整epoch行为。新状态文件记录Python或NumPy RNG类型，兼容原FC2旧格式；没有后台预取，正常记录区间边界可恢复随机状态。固定检查点保留修复仍有效。运行失败先检查日志，不覆盖或无条件重启同一输出目录。
